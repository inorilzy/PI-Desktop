turn-continue · 需求

插件的主动续跑 API：往宿主队列推一条消息。花的是真请求，署的是插件的名，走的是用户看得见的队列。

status: draft · issue #561 · 槽 runtime.turn.continue

范围 已核实

  • 一个主动 API：pi.continueTurn({ message })——回合结束后任意时刻可调。
  • 不谈：轮末被动询问（turn-closing）、模型请求改写（撤回）、静默注入（永不做）。

现状（代码核实） 已核实

  • 插件面已实现 + e2e：槽 runtime.turn.continue（trusted-extensions.ts:479），经宿主队列 session.queuePush 入列、带插件来源（runtime.ts:2794-2804）；e2e 在 trusted-extensions/seed.mjs:84,153 与 drive.mjs:173。总表「内部用了」只说对一半。
  • 署名落库：排队的轮是插件署名的可见行（ADR 0293，schema v22）。
  • 无配额：ADR 0295 规则 9 有意不设上限（0295:67）——控制手段是署名 + 可见 + 用户随时中止。
  • 同名不同物：内核的 steeringContinuation（runtime.ts:1822, 8189-8198）是 provider 恢复的内部路径，与本 API 无关。
  • 沙箱缺口：ADR 0292 broker 未建。

明确不做 已核实

  • 不允许无署名 / 隐藏的续跑轮——可见性是本 API 的存在前提。
  • 不允许插件冒充用户身份发消息——署名永远是插件。
  • 不提供后台无人值守模式——每轮都在用户的会话里、受用户的停止键管。
