before-request · 需求

已撤回的槽。本页回答三件事：它当初是什么、为什么收回、重开要先补什么。总表「本期不做」低估了决定——这是撤回，不是延期。

status: draft · issue #561 · 槽 runtime.request.before（撤回）

范围 已核实

  • 涉及 6 个内核事件：before_agent_start / context / before_provider_request / before_provider_headers / model_select / thinking_level_select——都曾被归入槽 6。
  • 不谈：发送路径的草稿改写（before-send，已开放）、工具层（gate / extend）。

现状（代码核实） 已核实

  • 撤回被强制执行：6 事件在 WITHDRAWN_RUNTIME_EVENTS（trusted-extensions.ts:420-433）；runner 不咨询其 handler 并报 rejected_registration（runner.ts:604, 682-687）。
  • 撤回是产品决定：ADR 0295 记录了「决定并随后收回」（docs/adr/0295:5, 63, 71-74），不是实现没跟上。
  • 内核挂点保留为透传：transformContext（runtime.ts:2051-2055, 2318）与 prepareNextTurn（明确无插件，runtime.ts:6267-6276）——重开时接线即可。
  • 重开排期：spec 把再引入列为 ADR 0295 分期步骤 3（16-trusted-extensions.md:636-641）。
  • 总表修正：「本期不做」应改「已撤回（可重开，需前置）」。

当初的契约形状（撤回前的设计） 已核实

方面内容
何时触发每次发模型前——一轮里可能多次（每批工具之后都有一请求）
拿到整份外发消息列表 + 模型 id + 思考量 + system prompt（撤回前形状见 TrustedExtensionRequestRewriteRecord，trusted-extensions.ts:294-322）
可返回改写（换消息列表）或两段式 { cancel, reason }
为什么收回。改写整份外发消息 = 无声的提示注入与历史删除：对话里不留痕、用户看不见、出错不可归因。没有审计与预算的地基，这个口子开不得。

重开的前置条件（建议） 建议

  • 审计面：plugin_rewrites 目前只收 outgoing_message（trusted-extensions.ts:303-308）——要加 message_list / request_payload 接收端，diff 级留痕。
  • 预算面：30 秒的结果性预算在请求热路径不可用——需要远小于此的同步预算或纯同步 handler。
  • 决定面：产品重新拍板「要不要让插件碰模型请求」，并写进 ADR。
