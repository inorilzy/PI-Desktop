abort-turn · 数据流

一次中止请求的往返：插件发起、桥接执行、布尔落定。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #561 · 字段名是建议值

1接口约定 建议

headless API，runtime.turn.abort（high）。无载荷，返回布尔。

// 插件 headless 任意位置（建议形态）
const accepted = await pi.requestTurnAbort()
// true  = 已受理，本会话在跑的轮开始中止
// false = 拒绝（没轮在跑 / 无权限），诊断已记
// 同时：本插件自己的长任务收到 ctx.signal 取消

语义表

方面内容
作用域只有本会话在跑的那一轮
返回true 受理 / false 拒绝 + 诊断（不静默）
伴随插件自己的工具 / 长任务同步收到取消信号
权限runtime.turn.abort，风险 high，装时确认

3出错怎么办 已核实

情况结果靠什么保证
没轮在跑false + 诊断bridge 状态检查
无权限permission_denied，不静默槽权限门控
中止失败（内核侧）按正常中止失败路径处理内核中止语义
插件反复刷调用现状不限速；用户可见中止来源装时确认 + 审计（限速待拍板）

4不提供什么 已核实

不给为什么
跨会话中止只作用本会话
伪造停止原因中止就是中止，没有自定义文案通道
中止 + 改写纯停；改写归 before-send
后台轮只看得见自己会话的轮
