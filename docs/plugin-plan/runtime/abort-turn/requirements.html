abort-turn · 需求

插件主动叫停在跑的一轮。高风险位：能杀掉用户的运行——装时确认 + 审计是仅有的对策，没有速率限制（因为只影响用户自己的会话）。

status: draft · issue #561 · 槽 runtime.turn.abort · 风险 high

范围 已核实

  • 一个主动 API：pi.requestTurnAbort()——不是事件、不是钩子询问。
  • 不谈：工具级拦截（tool-gate）、轮结束续跑（closing）、用户按停止键（宿主 UI）。

现状（代码核实） 已核实

  • 已实现：continueTurn 旁边的 requestTurnAbort，槽 runtime.turn.abort（trusted-extensions.ts:475, 550），风险 high（model.ts:63），已进权限矩阵文档（docs/spec/07-plugins/13-plugin-permissions-matrix.md:60）。
  • 实现点：runner.ts:1386-1390 → bridge.abort()；refusal 返回 false + 诊断，不静默。
  • 同一决定的两半：中止发同时，插件自己的长任务也收到取消（ctx.signal / 工具执行信号，runner.ts:1379-1383, 1168-1170）。
  • 「未开放」不成立：总表说法过时。

明确不做 已核实

  • 不让插件中止别的会话的轮——只有自己所在会话。
  • 不让插件伪造停止原因——中止就是用户可见的中止，没有静默通道。
