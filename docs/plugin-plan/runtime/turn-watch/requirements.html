turn-watch · 需求

一轮运行的过程流，插件全程可看、全程不可碰。这是 #561 里最接近「已经开放」的钩子——本目录主要是把现状写清、把契约钉死。

status: draft · issue #561 · 槽 runtime.turn.watch · 风险 medium

范围 已核实

  • 一轮运行从 agent_start 到 agent_end 的只读事件流。
  • 不谈：拦截与续跑（tool-gate / turn-closing / turn-continue）、工具结果改写（tool-extend）。

现状（代码核实） 已核实

  • 已对普通插件开放：11 个内核事件映射到 runtime.turn.watch（packages/shared/src/trusted-extensions.ts:178-189），已注册、已在 SDK 权限清单（plugin-sdk/src/index.ts:1863），风险 medium。
  • 「只给高信任」不成立：ADR 0295 §3 把高信任限制定性为「接线事故」并明确否决（docs/adr/0295:98-103）；总表的说法来自 ADR 之前的旧盘点。
  • 镜像而非直连：运行时把内核事件逐个镜像（runtime.ts:2372-2404），emit 是 fire-and-forget（runtime.ts:2404）。
  • 非结果性：不在 RESULT_EVENTS 里（runner.ts:126-142）——没有超时、没有回执、没有重投（ADR 0295 §10）。
  • 沙箱缺口：ADR 0292 broker 未建，沙箱插件进程接不到。

明确不做 已核实

  • 不让插件经 watch 改任何东西——返回值丢弃，无写路径。
  • 不保证送达——无回执、无重投、无顺序承诺（尽力而为）。
  • 不让 watch 承担安全职责——拦截去 tool-gate，续跑去 closing / continue。
