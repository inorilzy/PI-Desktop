turn-recap · 需求

插件的对话回读 API：轮范围看事实，会话范围看最近消息行。只读、拉取式、有上限。

status: draft · issue #561 · 槽 runtime.turn.recap · 风险 high

范围 已核实

  • 拉取式读取：插件自己调 pi.recap()，不是推送事件。
  • 不谈：轮过程观察（turn-watch）、写路径（无）、压缩前拦截（session-lifecycle 的 before_compact）。

现状（代码核实） 已核实

  • 已实现，非禁用：槽 8 API recap: "runtime.turn.recap"（trusted-extensions.ts:478），风险 high（model.ts:67）；实现走 host session.get（runtime.ts:2780-2786）。总表「桌面端禁了」不成立。
  • 会话范围要双权限：runtime.turn.recap + runtime.session.read（trusted-extensions.ts:490, 502-509）。
  • 单轮正文缺口：turn 范围返回 messages: null、messagesUnavailable: "no-host-turn-read"（trusted-extensions.ts:711-728）——一轮的对话文本在宿主侧没有读取口，这不是开关，是要新写的宿主能力。
  • 行数上限：默认 200，封顶 500（trusted-extensions.ts:512-515）。

契约（建议，待拍板） 建议

方面内容
调用pi.recap({ scope, turnId?, limit? })——拉取式，任意时刻可调
scope: "turn"返回该轮事实（状态、token、工具计数、动过的文件）；没有正文
scope: "session"返回最近消息行 + truncated 标记；默认 200 行，上限 500
权限runtime.turn.recap（high）；会话范围追加 runtime.session.read
单轮正文是独立缺口。想在 closing 钩子里看「这轮说了什么」来决定续不续——现在做不到：recap 给不了，需要宿主新开一轮文本读取（新宿主能力，不是解锁）。

插件场景（建议） 建议

#场景
1会话摘要卡片：定期拉最近 200 行，在自己面板生成摘要

3检索辅助：在会话行里做本地全文检索
