turn_end 之后、运行结束之前的一问一答。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #561 · 字段名是建议值

1接口约定 建议

headless 事件监听：插件注册 pi.on("turn_closing", …)，返回续跑意愿。结果性事件——有预算、有超时、第一个生效。

// 插件 headless 入口（建议形态）
pi.on("turn_closing", async (payload) => {
  // payload: { sessionId, turnIndex, stopReason }
  if (await testsFailed(payload.sessionId)) {
    return { continue: true, message: "测试没过，请修复后重跑一遍并汇报" };
  }
  // 不续：什么都不返回
})

能拿到什么 / 能返回什么

方面内容
输入{ sessionId, turnIndex, stopReason }
输出{ continue: true, message? }——message 缺省用宿主默认注入语；第一个续跑者生效，其余视为「不续」
预算每运行 4 轮封顶（现值）；续跑 = 正常 provider 请求
预算耗尽 / 超时不再询问插件，运行直接结束
权限槽级权限 + 装时确认；refusal 可见

一次运行的续跑链

时刻发生什么
第 1 轮完closing 询问 → 插件 A 续「修完重跑」→ 第 2 轮开跑
第 2 轮完closing 询问 → 都沉默 → 运行结束
预算用尽不再询问，运行结束（防循环）
用户中止不询问，立即结束

3出错怎么办 已核实

情况结果靠什么保证
插件超时 / 抛错视为不续，运行正常结束runner 预算与诊断
两个插件都要续第一个注册序生效，其余忽略first-wins 裁决
续跑请求失败按正常轮失败处理，运行结束内核循环
预算耗尽不再询问插件每运行 4 轮封顶
无权限permission_denied，不静默槽权限门控

4不提供什么 已核实

不给为什么
结束否决权插件只能「续」不能「拦」——不续即结束
对话记录写权续跑消息经宿主循环入列，插件不直接写行
整段对话payload 只有轮次与原因；要读历史走 recap API
无限续跑每运行 4 轮封顶
异常路径用户中止 / 报错不触发 closing
