turn-closing · 需求

一轮跑完、运行将停未停的窗口。插件可以给运行续上「再干一步」的消息——自动收尾、自动校验类插件的落脚点。#561 清单里唯一被标 ⭐ 的钩子。

status: draft · issue #561 · 事件 turn_closing · 槽 runtime.turn.closing

范围 已核实

  • 只管「这轮结束后、运行结束前」的一问一答：要不要续、续什么。
  • 不谈：轮中途的观察（turn-watch）、宿主主动续跑（turn-continue，另一个 API）、模型请求改写（已撤回的 before-request）。

  • 入口全在：内核 shouldStopAfterTurn 已接到 extensionTurnClosing，经 runner emit turn_closing（packages/agent-runtime/src/runtime.ts:2086-2093, 2335-2369, 2340）。
  • 0 消费者：全仓没有任何插件注册 pi.on("turn_closing")——没有示例、没有 e2e fixture；总表「入口全在、0 命中」属实。
  • SDK 缺件：plugin-sdk 没有导出 turn_closing 的类型化 payload（只有内部类型 extensions/turn-closing.ts:45-52）——开放给插件前要补。
  • 预算已在：每次运行最多续 4 轮（extensions/turn-closing.ts:38），续跑默认注入一条消息（turn-closing.ts:41-42），经 agent.steer(...) 进循环（runtime.ts:2368）。
  • 沙箱缺口：同所有钩子——ADR 0292 broker 未建，沙箱插件进程还接不到。

契约（建议，待拍板） 建议

方面内容
何时触发每轮正常跑完之后、运行可能结束之前；异常中止（用户停、报错）不触发
拿到{ sessionId, turnIndex, stopReason }——第几轮、为什么停
可返回{ continue: true, message? }——续一轮；message 缺省用宿主默认注入语；第一个续跑者生效，其余沉默、垃圾返回一律视为「不续」
预算每次运行 4 轮封顶（现值）；续跑花的是正常 provider 请求
权限槽级权限 + 装时确认（风险档待拍板）；refusal 可见不静默
续跑是花钱的。每续一轮就是一次真实的模型请求——预算、署名、用户可见性是这三件事让用户放心。

插件场景（建议） 建议

#场景

还没定的事 未定

明确不做 已核实

  • 不让插件否决结束——不续就结束，没有 veto。
  • 不让插件改对话记录或伪造轮次——续跑经 agent.steer 走正常循环，行是宿主记的。
  • 不做无限续跑——每运行 4 轮封顶，防插件把运行变成永动机。
  • 不在用户中止 / 报错路径上触发。
