before-send · 需求

发送路径上的唯一拦截点：用户消息已落库、未进 agent。插件可放行、改写、拦截。现状以代码核实为准——目录总表里「桌面端没 emit」的说法已被推翻。

status: draft · issue #561 · slot runtime.send.before · 风险 high

范围 已核实

  • 只管 rpc 发送路径上的一刻：用户消息已持久化、还没进 agent 循环。
  • 不谈：发送按钮与排队提示（输入区的事）、模型请求改写（before-request，已撤回）、审批卡。

现状（代码核实） 已核实

  • 已经在 emit：agent 运行时在发送路径上调用 extensionBeforeSend（packages/agent-runtime/src/runtime.ts:7856, 7951-8008），事件名 input，槽 runtime.send.before（packages/shared/src/trusted-extensions.ts:200）。总表「内核有、桌面端没 emit」不成立。
  • 信任档：槽风险 high，装插件时单独确认（apps/desktop/src/features/plugins/model.ts:58）；refusal 永远以 permission_denied 报出，不静默。
  • 改写有审计：transform 逐条记入 plugin_rewrites，diff 级别（runtime.ts:7994-8006）；用户消息行保留原文。
  • 沙箱插件还够不到：ADR 0292 的 broker 通道未实现——无注册 IPC、无注册表、无 2 秒预算、无熔断（docs/adr/0292-runtime-hooks-for-plugin-host-processes.md:13-25）。这是「未开」的真实含义。
分发机制是现成的。TrustedExtensionRunner.emit 统一按槽权限门控、拒绝已撤回事件、超时 30 秒按无意见处理（runner.ts:670-731）。

契约（建议，待拍板） 建议
