before-send · 发送后、入队前

用户消息已经落库、还没交给 agent 的那一刻。插件可以放行、改写文案、或带原因拦下这一次发送。运行时钩子在 agent 侧 headless 调用，没有界面，所以本目录没有演示页。

status: draft · issue #561 · slot runtime.send.before（风险：high）

一句话回顾

  • 现状已核实：agent 运行时已经在发这个钩子（runtime.send.before，事件名 input）——目录里「内核有、桌面端没 emit」的说法不成立；沙箱插件还够不到，缺的是 ADR 0292 的 broker 通道。
  • 三动作：放行（continue）/ 改写（transform，带新文案）/ 拦截（handled，带用户可读原因）。多个插件按注册顺序链式处理，改写逐条留审计。
  • 高信任位：能改写并拦下用户消息，风险 high，装的时候单独确认。
  • 不管：附件、已落库的用户消息行、发送按钮与排队（那是输入区的事）。

还没定的事

对普通插件开放还是先限高信任、handled 阻断的用户提示形态、预算时长——见 requirements.html 的「还没定的事」。
