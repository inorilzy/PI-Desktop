tool-extend · 需求

插件工具想变得更强：一次调用可以引出更多工具、把花费报给宿主、必要时请求整轮收工。能力是内核字段，开关是槽权限，归属是「谁的工具谁做主」。

status: draft · issue #561 · 槽 runtime.tool.extend

范围 已核实

  • 只管插件自有工具返回结果里的三个增强字段。
  • 不谈：别家工具的拦截与覆盖（tool-gate）、执行中途的事件流（turn-watch）、往循环追消息（closing / continue）。

现状（代码核实） 已核实

  • 内核字段在：AgentToolResult.addedToolNames / usage / terminate（pi-agent-core/dist/types.d.ts:317-331）。
  • 双端门控：运行时侧 applyExtensionToolCapabilities + toolResultExtensionAllowed（runtime.ts:2231-2262, runner.ts:996-1002）；Electron 主进程对无授权的插件剥离字段并审计 PERMISSION_DENIED（plugin-runtime.ts:1879-1899, host.ts:258-264）。
  • 标签纠偏：「工具执行期间」不准确——执行中的进度走工具自己的 onUpdate（镜像成 watch 事件）；追消息是 closing / continue 的事。
  • 总表「内核字段在」属实。

契约（建议，待拍板） 建议

字段干什么约束
addedToolNames本次调用往循环里引入新工具（下一轮模型可用）工具在界面上署名插件作者；受授权门控
usage上报本次调用的花费（token / 计数）展示位待拍板；数值仅供参考不进宿主结算
terminate请求整轮终止（批量收工）与用户中止同一收尾路径；不可伪造原因
权限runtime.tool.extend没授权 → 字段被剥离 + PERMISSION_DENIED 审计
归属边界。extend 是「自己工具的特权」：管不了别家插件的工具、管不了宿主工具——那边的字段会被剥掉。

插件场景（建议） 建议

#场景
1数据库工具：查完 schema 后按需引入「query_table」等后续工具，用到才注册

3批处理工具：跑完发现整体失败无意义，terminate 收工

明确不做 已核实

  • 不 gate 别家的工具——extend 不提供观察或拦截能力。
  • 不注入后续消息轮——那是 closing / continue 的通道。
  • 无授权不得越线——三个字段没授权就被剥离并审计，没有「读了再说」。
