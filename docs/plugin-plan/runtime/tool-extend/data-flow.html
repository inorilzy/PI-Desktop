tool-extend · 数据流

一次插件工具返回里的三个增强字段，怎么被宿主检查、放行或剥离。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #561 · 字段名是建议值，以内核类型为准

1接口约定 建议

不是一个调用，而是插件自有工具返回值上的三个可选字段；宿主按 runtime.tool.extend 授权决定收下还是剥掉。

// 插件自有工具的返回（建议形态）
return {
  content: "schema 已读取，共 12 张表",
  addedToolNames: ["query_table", "explain_query"],  // 引入新工具
  usage: { apiCalls: 1, rowsScanned: 1204 },           // 上报花费
  terminate: false,                                     // true = 请求整轮收工
}

字段表

字段宿主怎么处理
addedToolNames有授权 → 注册进循环，界面署名插件；无授权 → 剥离 + 审计
usage有授权 → 记录 / 展示；无授权 → 剥离
terminate有授权 → 走正常收尾；无授权 → 剥离
权限runtime.tool.extend；refusal / 剥离都留审计

3出错怎么办 已核实

情况结果靠什么保证
无授权带字段字段被剥离 + PERMISSION_DENIED 审计；结果主体照常双端门控
addedToolNames 引了不存在的工具无效名字忽略 + 诊断运行时校验
terminate 滥用走正常收尾路径，用户可见；与用户中止同源内核收尾语义
usage 数值离谱仅展示，不进宿主结算定位为参考值

4不提供什么 已核实

不给为什么
别家工具的 gate / 覆盖extend 是自有工具特权；拦截归 tool-gate
中途消息注入追消息归 closing / continue
无授权的字段生效双端剥离，没有例外
宿主工具的字段字段来自插件工具返回；宿主工具不经过插件
