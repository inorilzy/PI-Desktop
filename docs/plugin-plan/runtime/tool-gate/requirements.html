tool-gate · 需求

工具调用前后的守门位：拦得下、改得了结果、改不了参数。#561 里安全类插件（审计、防误删、合规）的主战场。

status: draft · issue #561 · 槽 runtime.tool.gate · 预算 30s

范围 已核实

  • 每次宿主 / 模型发起的工具调用的前后两个时刻。
  • 不谈：改参数（永久排除）、插件自己工具的结果增强（那是 tool-extend）、轮中途观察流（turn-watch）。

现状（代码核实） 已核实

  • 已接进内核循环：beforeToolCall → extensionToolCall（runtime.ts:2069, 2263-2277），afterToolCall → extensionToolResult（runtime.ts:2058, 2285-2314）；事件映射 runtime.tool.gate（trusted-extensions.ts:171-173）。
  • 结果性预算：30 秒，超时 = 无意见 + handler_timeout（trusted-extensions.ts:152, runner.ts:716-718）。
  • 「改参数不做」属实且永久：内核 BeforeToolCallResult 类型根本没有 args 字段（pi-agent-core/dist/types.d.ts:40-48）；ADR 0295 规则 4 连「包一层再改」的绕路也一并排除（0295:105-123）。
  • 折叠规则：拦截第一个 block 赢（runtime.ts:2274）；结果覆盖按字段合并（runtime.ts:2302-2313）。
  • 沙箱缺口：ADR 0292 broker 未建。

契约（建议，待拍板） 建议

执行前：tool_call

方面内容
拿到{ toolName, toolCallId, input }——校验过的参数
可返回{ block: true, reason } 拦下（reason 给模型看）；terminate? 顺带结束轮；不返回 = 放行
不能改 input——类型层面无此字段

执行后：tool_result

方面内容
拿到{ toolName, toolCallId, input, content, details, usage, isError, … }
可返回字段级覆盖：{ content?, details?, isError?, usage?, terminate? }——只覆盖给的字段，其余原样
不能改 input、把错误伪造成成功以外的语义混淆
慢确认是插件的 UI 义务。想「执行前问一下用户」：自己画界面（自理弹窗），决定后经 runtime.turn.continue 两段式处理——不许在 gate 里干等超过 30 秒（ADR 0295 规则 6）。

插件场景（建议） 建议

#场景
1防误删：执行前看 input，rm -rf 级别命令弹自己的确认，拒绝则 block + reason
2合规审计：记录每次工具调用与结果（result 事件里全量可见）
3结果净化：把结果里的密钥打码后覆盖 content
4失败重试包装：isError 时覆盖 content 附加诊断建议

明确不做 已核实

  • 不改参数——永久排除，含包装绕路（ADR 0295 规则 4）。
  • 不无限等待——30 秒封顶，超时无意见。
  • 不静默拦截——block 必须带 reason，每条决定可诊断。
  • 不 gate 别家插件工具的结果增强——那是 tool-extend 的地盘，归属不同。
