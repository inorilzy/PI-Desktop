tool-gate · 工具调用前 / 后

每个工具调用前后插件都被叫到：执行前可以带理由拦下，执行后可以改写结果呈现。唯一被永久排除的是改参数——内核类型里根本没有这个口。总表「改参数不做」属实，且是永久边界。

一句话回顾

  • 现状已核实：tool_call / tool_result 已映射到 runtime.tool.gate 并接进内核循环（30 秒预算，超时 = 无意见）。
  • 执行前：拿到工具名 + 参数，可返回 { block, reason, terminate? }——没有 args 字段，改参数在类型层面就不存在。
  • 执行后：拿到完整结果，可按字段覆盖 { content, details, isError, usage, terminate }，字段级合并。
  • 多插件折叠：拦截第一个 block 赢；结果覆盖按注册顺序字段级合并。
  • 不管：参数改写（永久）、无限等待（30 秒封顶）、静默拦截（每条决定可诊断）。

慢确认的 UI 义务、terminate 语义的插件可见性——见 requirements.html 的「本轮拍板（待定）」。
