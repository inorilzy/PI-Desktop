session-lifecycle · 需求

会话一生的观察位：建、删、切、fork、压缩。只有一个时刻可以拦——压缩前；其余都是通知。事件来源有两路：桌面 IPC 和 sidecar 内部。

status: draft · issue #561 · 槽 runtime.session.lifecycle

范围 已核实

  • 五个时刻：创建、删除、切换前、fork 前、压缩（前 / 成 / 败）。
  • 不谈：会话内容的读写（recap / facts）、轮内事件（turn-watch）、续跑（closing / continue）。

现状（代码核实） 已核实

  • 槽已注册并门控：runtime.session.lifecycle（trusted-extensions.ts:190-198, 546）。总表「事件够不到」不成立——内核确实没有这些钩子，但桌面端把事件接进来了（trusted-extensions.ts:328-352）。
  • 桌面来的四件：create / delete 直接 emit（session-ipc.ts:261, 453）；switch 经 announceActivation（session-ipc.ts:202-217）映射 session_before_switch（runtime.ts:8053-8059）；fork 同理（session-ipc.ts:317-324 → 8060-8066）。
  • sidecar 来的压缩：session_compact / session_compact_failed（runtime.ts:6393-6405）；session_before_compact 带压缩段且唯一有否决权（runtime.ts:8081-8099）。
  • fire-and-forget 为默认：除 before_compact 外全部不等插件（runtime.ts:8040-8043）。
  • 两个幽灵映射：project_trust / resources_discover 已映射但从不 emit（16-trusted-extensions.md:572-573）。
  • 边界：原生 Pi 会话听不到（桌面不经手的路径，session-ipc.ts:315-316）。

契约（建议，待拍板） 建议

事件拿到可返回
created / deleted会话标识与元信息无（通知）
before_switch旧 / 新会话 id无（不等待、不可拦）
before_fork源会话与 fork 目标无（不等待、不可拦）
before_compact压缩段：{ messages, messageCount, tokensBefore, retained }{ cancel: true } 可否决（30s 预算内）
compact / compact_failed结果通知无
权限runtime.session.lifecycle
否决权只给压缩。切会话、fork、删除都是用户的直接操作——插件只能跟着知道，不能拦（ADR 0295 规则 11）。压缩是后台自动行为，给插件一次「先别压，我还要读」的机会。

插件场景（建议） 建议

3fork 联动：fork 时把自己的会话级配置复制过去

明确不做 已核实
