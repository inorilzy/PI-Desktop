提示与浮层 · 数据流

插件调用 ui.confirm() 之后发生什么、参数怎么变成一张卡、用户点一下按钮真正发生什么。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · 字段名是建议值，还没进 SDK

1接口约定 建议

一个渲染进程动作 ui.confirm，走现有的 rendererActions 词表（ui.* 前缀），只能在插件渲染器代码里调用——headless 侧没有界面可画。

调用与返回

// 调用（插件渲染器内）
const choice = await pi.ui.confirm({
  kind: "confirm" | "choice" | "alert",
  title: "分支清理 · 确认删除",      // 一行文字，宿主排版
  description: "将删除 feat/528-plugin-slots 等 3 个分支",  // 固定字段的文案，宿主排版
  actions: [                        // ≤3 个；下拉候选也在这里声明
    { id: "cancel", label: "取消",     variant: "ghost" },
    { id: "delete", label: "全部删除", variant: "primary" },
  ],
})

// 返回
"cancel" | "delete" | "ok" | actionId
// 插件被禁用 / 卸载时：
{ choice: "cancel", reason: "plugin-unloaded" }

参数的边界

方面是什么
内容只有参数：title + description 固定字段，宿主排版。不接受组件、不让自绘——卡片里没有插件渲染的界面
按钮配置（actions）：文案、档位（ghost / secondary / primary）、下拉候选；样式宿主固定
权限属于 renderer 档（renderer.extension），不单列权限
出错面卡片里没有插件代码在跑——排版和按钮都是宿主的；插件侧唯一会出错的是调用参数本身的校验
拿不到的东西按钮区、卡壳、宿主权限审批卡的数据、会话数据

没有自理弹窗的接口——那是另一个模块：ui/self-dialog/（插件自理，宿主不经手任何数据）。本页只讲 ui.confirm。

确认卡的一生

时刻发生什么
调用插件 await pi.ui.confirm(...)，卡片进队列；队列里排在前面的先显示
上屏轮到它时，横栏出现在消息流末尾；内容参数由宿主排版上屏
显示中内容是定格的参数文案；不响应 Esc；不超时
点击用户按下按钮 → Promise 落定为该按钮的 id → 卡片移除，下一张上屏
卸载插件被禁用 / 卸载 → 卡片（含排队中的）移除，挂起的 await 落定 cancel + plugin-unloaded
权限请求随时插队。权限审批卡出现时立即顶到最前显示，插件确认卡退回队列折叠成条；权限卡处理完按原顺序恢复。这是安全优先，不是公平队列。

3出错怎么办 一定会遇到

情况结果靠什么保证
调用参数不合法调用被拒绝并带错误码（如按钮超限、字段缺失），不产生卡片；诊断记在插件行上入参校验
插件被禁用 / 卸载显示中的卡片移除、排队条目移除、挂起的 await 落定 cancel + 原因码插件生命周期清理
自理弹窗抛错不经过本模块——自理界面的出错与清理见 ui/self-dialog/槽级出错隔离罩住插件组件树
确认卡与自理层的关系自理层永远压不过确认卡与权限审批卡（宿主最高层带）z 序底线，见 ui/self-dialog/

4不提供什么 已定

不给为什么
宿主审批卡的接管 / 重画那张卡是安全决策面，只属于宿主；旧接管槽取消
确认卡里的按钮区按钮是配置 + 宿主样式，插件碰不到；交互结果只有「哪个按钮被按下」
层机制确认卡不走注册、不参与仲裁（自理层的规则见 ui/self-dialog/）
会话 / 消息数据确认卡只负责问用户；卡片拿不到会话内容，内容只有插件传来的参数
决策路径确认卡不进权限队列的决策：允许 / 拒绝永远走宿主审批卡
