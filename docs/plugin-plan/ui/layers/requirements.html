提示与浮层 · 需求

插件向用户要一次确认怎么办：ui.confirm() 固定格式确认卡。宿主不养层机制，插件不能接管权限审批卡。要全屏弹窗 / 角落浮层 → ui/self-dialog/（插件自理，另立文件夹）。

status: draft · issue #545 · 对照 demo.html · 数据流

范围 已定

  • 确认卡：插件向用户发起一次确认 / 选择 / 知会，走渲染进程 API ui.confirm()，固定格式，点击回调。
  • 不谈：弹窗 / 悬浮层的插件自理（另立文件夹 ui/self-dialog/）、宿主自己权限审批卡的内部实现（宿主的事）、ui.toast（已有）、通知中心。

确认卡 · 固定格式 已定

一条横栏，不是居中弹窗：与输入框同宽（窄 5px）、紧贴输入框上方、无间距、无底部阴影；左边内容、右边按钮。卡壳、位置、按钮样式全是宿主的。

部分归谁说明
位置 / 卡壳宿主消息流末尾、与权限审批卡同一个位置；宽度、边框、圆角、排版固定
标题插件（参数）一行文字 + ui.confirm 来源徽标
内容插件（参数）固定字段的文案（描述 / 明细行），宿主排版；不接受组件、不让自绘——要自由界面走 ui/self-dialog/
按钮插件（配置）/ 宿主（样式）actions: [{ id, label, variant }]，≤3 个；样式宿主固定，文案插件给；支持下拉形态（主钮 + 箭头展开候选）
结果宿主 → 插件用户点击后 Promise 回调按下的 actionId / "ok" / "cancel"

三种卡型 已定

卡型按钮结果
confirm 确认2 钮（取消 + 主操作）"ok" | "cancel"
choice 选择主操作 + 下拉候选（≤3 项）按下的 actionId
alert 知会1 钮"ok"

排队与兼容 已定

  • 权限请求永远第一优先：宿主权限审批卡出现时立即插队显示，插件确认卡退回队列、折叠成一条（只留标题 + 排队中徽标），权限卡头部显示「确认卡 N 张等待」。
  • 插件确认卡 FIFO：同队列一次只显示一张，其余折叠成条；与权限卡的「队首 + 计数徽标」同款语义。
  • 不响应 Esc：与权限审批卡一致，必须点按钮。
  • 不设超时：权限卡的倒计时超时自动拒绝是安全设计，确认卡不沿用；插件卸载是唯一的服务端取消。
  • 插件被禁用 / 卸载：显示中的卡片移除，排队中的条目移除，所有挂起的 await 收到 { choice: "cancel", reason: "plugin-unloaded" }。
不提供接管。插件不能认领、重画、替换宿主的权限审批卡——那张卡只属于宿主。旧 inlineConfirm 接管槽在重设计中取消。

本轮拍板 已定

问题结论
确认卡是插槽还是 APIAPI（ui.confirm()）。固定格式：卡壳宿主、内容走参数、按钮配置化、点击回调。不提供接管宿主审批卡
ui.confirm 属于哪一档属于 renderer：权限归 renderer 档（renderer.extension），不单列权限
确认卡长什么样与输入框同宽（窄 5px）紧贴其上的横栏，左内容右按钮；不是居中弹窗、无遮罩
按钮形态单钮或下拉选择钮（主钮 + 箭头展开候选）；≤3 个；样式宿主固定
内容怎么来只传参。固定字段的文案（标题 + 描述），宿主排版；不做内容组件、不让自绘——动态 / 自由界面走自理弹窗（ui/self-dialog/）
modal / overlay 槽取消。注册制（modal 先注先得、全局一个）堵其他插件的路；弹窗 / 悬浮层改插件自理，另立文件夹 ui/self-dialog/；现有 ui.openModal 等四个动作移除（实现批次处理）
多插件同时要浮层后开的在上，宿主不仲裁——见 ui/self-dialog/ 四条底线
inline-confirm 接管语义取消。宿主权限审批卡不可认领、不可改画

和现状的关系 边界改口

这是产品设计决定，不是实现漏项。实现侧的迁移（删槽位、删动作、改 showcase 示例与测试）排批次处理，不在本目录。

现状（已实现，spec 07-plugins/16 §2A.5–2A.7）

  • inlineConfirm 接管槽：插件重画宿主权限审批卡
  • modal replace 槽：先注先得，全局一个
  • overlay additive 槽 + ui.openModal / ui.closeModal / ui.openOverlay / ui.closeOverlay 四个动作；「层的出现即注册」

重设计

  • ui.confirm() 固定格式确认卡（渲染进程 API）
  • 弹窗 / 悬浮层自理 → ui/self-dialog/（独立文件夹，含样式说明）
  • 接管槽、modal / overlay 槽、四个层动作全部移除

还没定的事 未定

  • confirm 卡型是否自动补「取消」钮（插件只给主操作时）。
  • 下拉候选的 variant 是否允许每项单独定（当前建议整钮一档）。
  • choice 卡型下拉候选的键盘导航细节。
  • 描述文案允许的长度与换行（超长截断还是撑高横栏）。

明确不做 已定

  • 不让插件接管、重画、替换宿主的权限审批卡，也不让改确认卡的卡壳和按钮样式。
  • 不给宿主层机制：确认卡不走注册、不参与抢注仲裁（弹窗 / 悬浮层的自理规则见 ui/self-dialog/）。
  • 不做居中遮罩式的宿主确认 API——确认卡就是输入框上方那条横栏。
  • 不让确认卡进宿主权限队列的决策路径：卡片只是问用户，决策（允许 / 拒绝）永远走宿主审批卡。
