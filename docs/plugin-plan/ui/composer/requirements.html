输入区 · 需求

聊天输入框这一块：工具栏左右两排、打触发符弹出的列表、输入框里的记号，外加读写草稿和附件两组方法。固定件不动，其余交给插件。

status: draft · issue #545 · 对照 demo.html · 数据流

范围 已定

  • 输入框工具栏：左右两排按钮里的插件位置。
  • 输入框上方弹出的列表：插件注册的触发符（如 #）触发的选择列表。
  • 输入框里面的记号：选中的东西（如 【#数据1】）在草稿里长什么样。
  • 两组方法：读写草稿（拿到输入框文字、往里写）、读写附件（拿到当前附件列表、写入附件）。
  • 不谈：发送流程本身（消息怎么入队、能不能撤回）、输入框上方的改动审阅卡、排队提示。那些是别的槽或宿主自己的事。

固定件 已定

这些控件插件碰不到：不隐藏、不替换、不排序、不在它们中间插东西（左排固定件右边、模型选择左边除外）。

槽位划分 已定

槽 / 方法位置插件能做什么
composer.left左排固定件（附件 / 模式 / 权限）的右边加自己的按钮和弹层（知识库选择、常用语……）
composer.middle右排、模型选择的左边这一段加自己的按钮；宿主现成组件 ContextUsage（上下文用量）整项交给插件处置：可隐藏、可显示、可重排、可替换
composer.trigger打字时输入框上方弹出的列表注册一个触发符号，提供列表内容（可远程拉取）
composer.content输入框内的记号（chip）触发符选中项在草稿里渲染成的样子
composer.readDraft方法 · 归 api/ · 权限同名读取输入框文字和记号列表
composer.writeDraft方法 · 归 api/ · 权限同名往输入框写文字；新记号用占位符、既有记号按宿主的 key 引用回写；替换与光标处插入两个动作
composer.attachments方法 · 归 api/ · 权限同名附件三动作：加（内容插件自存，登记地址）、列（当前附件列表，含来源标记）、移（只能移除自己加的）
中槽里宿主的东西只有「上下文用量」——它是一个现成组件（ContextUsage），默认装在中槽里，整项交给插件处置。插件通过排序声明决定它显示不显示、排在哪；也可以藏掉它换成自己的（比如更细的用量显示）。插件出错或卸载时，宿主按默认布局把它画回来。组件与排序声明见 data-flow.html。
宿主的「提示词增强」移除（第三轮重申）。宿主不再提供这个按钮，能力由插件实现（demo 场景 4）。两轮口径矛盾就此了结：按「增强不存在」设计。

触发符 已定

  • 注册制（已定）：插件在清单里声明一个触发符号（如 #），单个字符。用户打出符号后，输入框上方弹出选择列表。
  • 触发后输入是筛选（已定）：符号后面的文字作为筛选条件交给插件；文字里出现空白，弹层关闭。
  • 样式固定、内容自定义（已定）：弹层的外观、交互（键盘上下选、回车确认）是宿主的；每一行里给什么图标、标题、描述、快捷记号，是插件的。
  • 数据可以远程拉（已定）：列表数据由插件取，包括去远程拉，避免主进程卡顿；宿主给加载态。
  • 选中后插入记号（已定）：选中项在草稿里是一个不可拆的记号（chip），可以整体删除，不能从中间编辑。数据格式见下一节。
抢注冲突（已定）：两个插件注册同一个触发符号，安装时提醒；硬要安装以先安装者为准，后装者的这个符号不生效。/ 和 @ 是宿主自己的，不对插件开放。

记号的数据格式 已定

触发符选中一项、或插件往输入框写记号时，插件一次性给三样，宿主各用各的：

字段给谁看说明
label人记号上显示的字（如「知识库1」）。宿主不解析它
sendAI发送时替换记号所在的位置，三种形态：text（展开成文字插回原位，如 #datadb:type2:id:1，或直接内联一段内容）、attachment（变成结构化附件，走宿主现有附件通道）、none（不发送，只是输入框里的元信息，编辑锚点用这种）
payload插件自己任意数据。宿主原样存、原样还，永不解析
记号字符由宿主分配。插件写草稿时用占位符（如 {{t1}}）并随附记号数据，宿主把占位符换成自己的内部字符并登记记号表。插件不接触内部字符。
手打的 #知识库1 不是记号。只有触发符选中、或插件通过占位符写入产生的才算。按文字样式反推记号要处理歧义和输入法，不做。
发送时不问插件。选中那一刻数据就齐了，发送只是宿主机械展开。大内容用 text 放一个引用串，AI 需要细节时通过插件提供的工具去取。
记号外形宿主固定（已定）。样子是【icon | 文字】：icon 用选中列表项时的图标，文字是 label。插件不能换外形，和 @文件 引用一致。

编辑历史消息 已定

点已发送消息上的「编辑」，不再在消息行里就地编辑，而是回填到底部输入框：

  • 锚点记号：输入框里出现一个宿主自己的记号（chip），显示被编辑那条消息的原文预览，超长隐藏。和 @文件 引用是同一套机制、同一种行为。
  • 正文可编辑：锚点后面是那条消息的可编辑形态，原消息里的记号还原成 chip。
  • 删锚点 = 退出编辑：输入框里已有的文字原样留着，这条草稿变回一条普通新消息。
  • 同时只有一条：编辑中再点另一条的「编辑」，直接清空输入框、回填新的。不做保护——正在改的未发送文字直接丢弃（拍板：不提示、不还原）。
  • 发送（已定：截断重跑）：走普通发送逻辑，不造第二条出站通道。有锚点时，先删掉被编辑那条消息及其之后的对话，再把编辑后的内容作为那条消息重新发送（和现在的行内编辑一致）。
锚点记号的发送形态是 none：它是输入框里的元信息，不是发给 AI 的内容。

读写草稿与附件 已定

三个方法、三个权限。权限名与动作名一一对应，归类到 api/（不是界面槽）：

  • composer.readDraft — 输入框当前文字、记号列表；payload 只还给写入它的那个插件。
  • composer.writeDraft — 往输入框写文字；覆盖「整体替换」和「光标处插入」两个动作。新记号用占位符写，既有记号按宿主分配的 key 引用回写；replace 是所见即所写。
  • composer.attachments — 附件三动作，一个权限：
    • 加 — 内容由插件自己存（存哪里由插件开发者决定），插件拿到地址后登记进附件区（{ name, mimeType, ref }，名字必须带扩展名，ref 是插件侧的地址：本地路径或 URL）。宿主不存内容，只登记显示、画缩略，返回 id。
    • 列 — 当前附件列表，每条带来源标记（用户加的 / 哪个插件加的）。
    • 移 — 只能移除自己加的；用户加的、别的插件加的，拒绝。
writeDraft 没有宿主级撤销（已定）。插件配合 readDraft 自己实现：先读、把旧快照原样存下，撤销时重新读一次拿新版本号，再把旧快照原样回写（既有记号按 key 引用带上）。拿旧版本号写会被拒。

本轮拍板 已定

问题结论
哪些控件固定附件、模式切换、权限切换、模型选择、发送 / 停止。插件碰不到
中槽插件能不能隐藏 / 替换宿主项能。宿主在中槽的默认项只有上下文用量，插件可隐藏或替换。目的就是让插件自己实现增强这类能力
宿主的提示词增强移除。按「增强不存在」设计，能力由插件实现（demo 场景 4）。第三轮重申，两轮矛盾了结
触发符弹层样式宿主固定；列表项内容由插件给
列表数据来源插件自己取，可以远程拉，避免主进程卡顿
选中后插入什么不可拆的记号（chip）；发送时由宿主按结构化数据机械展开，不问插件
分支上旧的 ComposerControlSlot 原型废弃重做。旧 beforeSend 是把模型 + 上下文 + 增强整块移交给一个插件，与新边界（模型 / 发送固定、增强移除）冲突

补充拍板（第二轮） 已定

问题结论
读写草稿、写附件怎么分类不是界面槽，归 api/ 类。三个权限：composer.readDraft、composer.writeDraft、composer.attachments（附件三动作：加 / 列 / 移一个权限；移只能动自己加的）
中槽多个插件怎么排序按声明（注册）顺序，不引入排序字段
触发符支持到什么程度单符号（一个字符）；触发后输入的文字是筛选条件
两个插件抢同一触发符安装时提醒；硬装以先安装者为准，后装者该符号不生效
writeDraft 的撤销宿主不做，插件配合 readDraft 自己实现
记号怎么写入插件用占位符写、宿主分配内部字符；插件一次给 label（显示）和 send（发送）两份数据，见「记号的数据格式」
手打的 # 算不算记号不算。必须通过触发符选中或插件写入产生
编辑历史消息的入口回填底部输入框 + 锚点记号，不再在消息行里就地编辑；同时只编辑一条，切换直接清空、不做保护

第三轮拍板 已定

问题结论
宿主的提示词增强维持移除（第三轮重申）。宿主不再提供，能力由插件实现；两轮口径矛盾就此了结
中槽的排序权归谁归插件。宿主默认项「上下文用量」整项交给插件处置：可隐藏、可显示、可重排、可替换。插件之间仍按声明顺序，槽内顺序由各插件的排序声明决定（字段见 data-flow.html）
附件方法名统一为 composer.attachments（加 / 列 / 移一个权限）；旧名 composer.addAttachment / getAttachments 作废
接口定义的详细程度data-flow.html 每个接口写清传什么、返回什么、错误情况，配调用示例和示例场景（文字场景，不是界面演示）

第四轮拍板 已定

问题结论
发送按钮右边的插件位置不留。发送 / 停止永远最右，右边不加插件位置
编辑发送的语义截断重跑：先删掉被编辑那条及其之后的对话，再把编辑后的内容作为那条消息重发
记号随历史消息持久化契约对齐斜杠命令的存法；实现排在最后，之前编辑旧消息看到的是展开后的文字
记号外形宿主固定，【icon | 文字】格式；插件不能换
触发符弹层样式与防抖按建议值拍板：四态样式宿主固定，输入防抖采纳建议（具体数值实现时定）
卸载后残留记号退化为普通文字，显示记号的 label（txt）
插件附件的存法内容确实是插件生成的，但存在插件自己决定的地方，插件拿到地址后只把地址登记进附件区（add({ name, mimeType, ref })）。宿主不存内容；发送时宿主按地址取回，当正常附件随消息发送

第五轮拍板（接口） 已定

问题结论
read 快照能不能直接写回能。writeDraft 的 text 接受 read 给过的内部字符，既有记号按宿主分配的 key 引用回写（宿主用登记表里的原数据）；{{名字}} 占位符只在写新记号时用
replace 会不会吞掉别人的记号所见即所写：新 text 里没有的记号就是删了；要保住就引用带回。记号登记表按会话只增不删，被删的记号也能凭 key 还原（撤销依赖这一点）
key 谁来分配宿主在登记记号时分配，全程稳定；触发符选中的记号同样有 key
payload 跨插件可见性payload 只还给写入它的那个插件，别人的 read 里该字段省略；label / send 可见是有意的（宿主渲染和发送都要用）
版本号什么时候推进每次草稿变化都 +1：用户打字、删改、插件写入都算。防止插件用旧 baseVersion 静默覆盖用户刚打的字
写入的并发与会话校验write 必须带 sessionId（对不上当前会话整次拒绝）；baseVersion 在宿主提交时刻单线程比对，先到先得，后到拒绝；内部字符只认当前会话登记表
宿主记号的保护编辑锚点等宿主自己的记号，插件不可删除、不可引用；replace 的 text 里丢掉它 → 整次拒绝。send.attachment 的 id 只能引用本插件登记的附件
附件 id 失效怎么办地址取不到 / 超限 / 登记已被移除：发送时统一校验，阻断这次发送并报错（同一条路径）；用户移除失效的 chip 后可重试
插件卸载后中槽怎么算按剩余插件的声明顺序重算；没人表态 ContextUsage 回默认位置。附件登记随会话走，切会话即清空
插件附件的接口形状维持现状：内容插件自存、登记地址 add({ name, mimeType, ref })，发送时按地址取回当正常附件发

和 #545 原文的关系 边界改口

#545 原文仅供参考，边界以本页为准。这是产品决定，不是实现漏项。

#545 原文的想象

  • 左右两排各留一个槽，插件随便加东西
  • 引用、补全、附件源、草稿改写是四个独立的点

本轮决定

  • 固定件收死：模式 / 权限 / 附件 / 模型 / 发送不许动
  • 中槽可以隐藏 / 替换宿主项——宿主增强移除，交给插件
  • 触发符 + 记号 + 解析连成一条线；草稿与附件读写是两组方法

还没定的事 未定

  • 触发符号的字符集：emoji、全角等算不算「单个字符」，SDK 定字段前要拍板。

明确不做 已定

  • 不让插件动五个固定件，也不在固定件中间插东西（左排固定件右边、模型选择左边这两个开口除外）。
  • 发送 / 停止右边不留插件位置（第四轮拍板：不留）。
  • 不让插件碰发送按钮的行为：拦截发送、改发送内容不属于输入区（解析记号是唯一出口）。
  • 不给整段对话历史——草稿和附件方法只针对当前输入框。
  • 不让插件在输入框里画任意自由界面：中槽 / 左槽是按钮级，弹层列表是固定 chrome。
  • 输入框上方的改动审阅卡、排队提示不在本目录。
