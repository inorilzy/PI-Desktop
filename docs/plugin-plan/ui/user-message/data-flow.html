用户消息卡 · 数据流

插件能拿到什么、自己画什么、点一下按钮真正发生什么。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 第 1 项 · 接口里的字段名是建议值，还没定

1接口约定 建议

权限名用 renderer.extension：一个权限名管所有组件插槽，不用每个槽单独授权。

插件能拿到的数据

// entry 和 entry.actions 收到的全部输入
{
  entry: { id, role: "user" },   // 任何插件都能渲染，不看这条是谁产生的
  message: {
    text,                       // 用户打出来的原文（改写之前）
    attachments: [              // 只有文件信息，没有文件内容
      { ref, name, kind: "image" | "file", mimeType, size }
    ],
    command,                    // 斜杠命令才有
    revision: { current, total } | null,   // 改过几版，没改过就是 null
    createdAt, streaming
  },
  sessionId
}

宿主提供的现成组件

插件可以直接用，也可以不用、自己画。不是必须套的外壳。

组件画什么不用它的话，插件要自己做什么
UserBubble默认气泡的外壳 + 附件 + 文字整个气泡自己画
UserAttachments图片缩略图 / 文件芯片（点击能打开）附件的样式和点击自己处理
UserText正文（其中的文件路径、网址会自动变成可点链接）正文自己画，链接也要自己处理
RewriteBadge改写徽标（可以展开）插件用了 entry，默认卡就不显示徽标；插件要自己决定还显不显示
ActionBar复制 / 编辑 / 删除 / 修订，可以隐藏其中某项，也可以加自己的按钮操作栏整排自己排

插件能调用的操作

操作做什么什么时候不能用
copy()复制消息里存着的原文（不是插件画在屏幕上的字）这条没有文字
edit()进入宿主的编辑状态；插槽让开，宿主的编辑框接管这条消息正在回复中 / 协作转发的消息
delete()删除这条消息（会走宿主的确认）正在回复中 / 协作转发的消息
setRevision(n)切到第 n 版只有一版，没有可切的
openAttachment(ref)用宿主现有的方式打开附件（工作面板 / 文件视图）找不到文件时给个提示
插件可以让某个按钮不显示，但换不掉这些操作本身的行为。藏掉按钮不等于把功能废掉。

2数据怎么走 建议

host 宿主页面 slot 插槽边界 plugin 插件组件
宿主（消息这一行）
<PluginSlot> 插槽
插件组件
  • message + sessionId这条消息的全部数据，一次给全
  • 现成组件UserBubble / ActionBar 等
  • 操作函数跟这条消息绑定，不是一串名字
  • 出错隔离每个插槽单独隔开
  • 带插件 id 的外层容器插件的样式只在这里生效

  • 插件被关掉后界面上不留位置
  • 画界面用现成组件，或整个自己画
  • 自己管状态折叠、按钮进行中
  • 调用操作copy / edit / delete…
  • 加样式必须通过宿主提供的样式接口

两个槽各拿什么

entryentry.actions
位置消息气泡整体气泡下面那一行
拿到这条消息的数据 + 正文相关的组件这条消息的数据 + 操作栏组件 + 各个操作
典型改写把 token 打码、重排附件、整个气泡自己画加「在看板打开」、藏掉编辑
什么时候重画这条消息重新渲染时重画；插件自己的状态要自己保存跟着操作栏出现 / 隐藏（鼠标悬停时）

谁能用这两个槽

规则
谁任何插件都能渲染这两个槽，不看这条消息是谁产生的
范围对所有用户消息生效，不按来源过滤
插件能改哪一块能增删的只有操作栏；消息气泡整体是整块替换，不做局部增删
本轮不做「分享整段对话为图」，也不做「PDF 点一下就能看」。插槽拿到的数据只有这一条用户消息，助手的回复走另一套组件，不在消息这一行的数据里。

3出错怎么办 一定会遇到

情况这条消息会变成什么靠什么保证
组件报错 / 卡死换回默认卡；旁边的消息不受影响每个插槽独立的出错隔离
插件被关掉 / 崩溃 / 禁用自动变回默认卡，界面上不留空位插件不在就不占位置
用户点了编辑插槽让开，宿主的编辑框接管这条消息宿主自己的编辑状态
插件没声明 renderer 入口跳过注册，普通插件不受影响信任档
插件没声明 renderer 入口跳过注册，普通插件不受影响信任档
挡不住的：受信插件故意把界面画坏，比如把原文藏起来、把所有按钮删光。它和宿主跑在同一个页面进程里，这是已经接受的代价。能保证的是：它改不了数据库里的内容，也弄不垮整场对话。

4不提供什么 已定

不给为什么真需要就走哪
文件内容附件只给文件名、路径、类型、大小openAttachment 交给宿主打开
整段对话插槽只管这一条消息，不该背着整个会话本轮没有这条路（分享场景已移除）
改数据库的权力改写和删除必须由宿主来做上面那组操作
助手的回复助手走的是另一套组件助手气泡的槽下一轮单独谈
旁边的消息、别的会话插槽只拿到这一条没有这条路
