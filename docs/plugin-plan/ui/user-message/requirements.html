用户消息卡 · 需求

用户发出去的那一行。两个槽：消息气泡整体 entry、操作栏 entry.actions。槽挂在默认卡上，不另造一张卡。

status: draft · issue #545 第 1 项 · 对照 demo.html / data-flow.html

范围 已定

  • 只谈用户那一行（MessageRow，role=user）。
  • 用户发出去的只有 附件 + 文字。
  • 不谈：助手 Turn、工具卡、Composer、确认卡、全局浮层。

槽有几个 已定

槽位置插件能做什么
entry消息气泡整体（附件和文字怎么显示）改写显示方式；可以用宿主现成的组件，也可以整块自己画
entry.actions操作栏（气泡下面那一行）加自己的按钮；去掉宿主的复制 / 编辑 / 删除
已去掉 entryExtra。行下追加不再单独成槽；要加东西就走 entry 包默认气泡，或走 entry.actions 旁边加控件。

槽必须提供三件套 已定

件含义
现成组件宿主把默认卡的各部分做成现成组件给插件用，插件在默认卡上加东西，不用从零再画一张
完整数据显示这条消息需要的数据一次给全，插件不用猜、也不用从页面上扒
能调用的操作复制 / 编辑 / 删除 / 修订是能直接调用的宿主功能，不是 "copy"|"edit" 这样的名字

目的：插件把界面画坏了，最多是这条消息不好看；消息怎么存、编辑怎么进行，还是宿主说了算。

默认卡长什么样 已定

最小默认（宿主，无插件）

  • 右对齐气泡，列宽 ≤600px，右下小圆角
  • 附件：图缩略图 / 文件芯片
  • 正文
  • 操作栏：复制 / 编辑 / 删除

拓展默认（仍是宿主，不是槽）

  • 改写徽标（可展开）
  • 修订翻页 2/3

插件场景 已定

这一轮留下的两件事，以及各自挂在哪。

#场景挂在哪
1去掉消息操作栏上的编辑按钮entry.actions 拿掉 Edit
2修改附件的样子entry 里自己画附件，或包一层宿主附件组件
本轮移除的两个场景：「分享整段对话为图」和「PDF 点一下就能看」——先不做，需要时另开。

本轮拍板 已定

问题结论
谁可以用这两个槽任何插件都能渲染这两个槽；对所有用户消息生效，不再按「这条是不是插件产生的」过滤
插件能改默认卡的哪一块插件能增删的只有操作栏；消息气泡整体是整块替换，不做局部增删
复制给什么给存着的内容，不是插件画在屏幕上的字
entryExtra用户气泡上不再有这个功能；助手气泡下一轮再谈

和 #545 原文的差异 产品改口

这是产品决定，不是实现漏项。落地时要改 issue / 契约，不能假装原文已经这样写。

#545 原文

  • 第 1 项管整条消息；举例是 Slack / 告警 / 周报对象卡
  • actions 语义由宿主提供，插件可摆位、不能删
  • 第 13 项条目追加区挂在条目下方

本轮决定

  • 用户卡仍是附件 + 文字；对象卡不是主故事
  • 操作栏 可补可删
  • entryExtra 从用户气泡拿掉

接口长什么样（建议，还没定） 建议

下面是我提议、用来支撑上面三条的东西。不是用户原话；字段名开工时再定。完整版见 data-flow.html 的第一节。
  • 现成组件：UserBubble / UserAttachments / UserText / RewriteBadge / ActionBar，想用就用，不是必须套的外壳。
  • 能拿到的数据：id / role / text / attachments / command / revision / createdAt / streaming。
  • 能调用的操作：copy / edit / delete / setRevision / openAttachment。
