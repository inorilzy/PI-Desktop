弹窗与悬浮层 · 插件自理

插件要全屏弹窗或角落浮层时，在自己的组件里用 position: fixed 自己画。宿主不设槽、不注册、无抢注——约束只有四条底线和一套推荐样式。

demo.html

推荐样式：模态弹窗（遮罩 + 居中卡）、角落悬浮层（非阻塞通知卡）、z 序边界——按宿主浮层家族的形态画。

不写说明文字，只有界面

没有「数据流」页：自理弹窗不经过宿主——没有接口、没有数据往来，这在 requirements 的拍板里记录。

一句话回顾

  • 自理：插件和宿主同一页面、同一 React，插件在自己的组件里 position: fixed 自画；禁用 / 卸载时随组件树消失，无需宿主收拾。
  • 为什么不设槽：旧 modal 注册槽先注先得、全局一个，第一个注册的插件堵死所有其他插件的路。
  • 四条底线：画在自己组件里（不 portal 到 body，丢样式作用域）；卸载即消失；永远压不过宿主的审批卡；插件互相之间后开的在上，宿主不仲裁。
  • 交互规则：Esc 不关闭；关闭只走 ✕ 钮（点遮罩不关）；只悬浮层建议支持拖动（手势随工具类提供），弹窗不拖、不记位置。
  • 推荐样式与工具类：模态照 .search-overlay / .search-dialog 家族、悬浮层照 .update-notice / .toast；宿主打包成官方工具类（pi-dlg / pi-notice 等，pi- 前缀稳定公共面）+ 全部用 --ds-* 主题 token 上色。
  • 与确认卡的分工：要问用户一句话 → ui.confirm()（ui/layers/）；要自由界面 → 在这里自理。

还没定的事

建议样式是否打包成插件可用的工具类、Esc 语义建议、多插件并发的协调机制——见 requirements.html 的「还没定的事」。
