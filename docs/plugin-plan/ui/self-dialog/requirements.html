弹窗与悬浮层 · 需求

插件自理的全屏弹窗和角落浮层：没有宿主机制，只有四条底线和一套推荐样式。样式说明落在实处——用组件库的哪些现成形态、主题 token 长什么样、z 序带怎么排。

status: draft · issue #545 · 对照 demo.html · 无数据流页（宿主不经手任何数据）

范围 已定

  • 弹窗（模态，带遮罩、阻塞）：插件自己画的对话框。
  • 悬浮层（非阻塞）：角落小浮层、迷你状态条等，不挡聊天。
  • 不谈：向用户要一次确认 → ui.confirm()（ui/layers/）；宿主自己的对话框与权限审批卡。

机制：没有机制 已定

  • 无槽、无注册、无抢注：任何插件随时可以画。旧 modal 注册槽「先注先得、全局一个」会堵死其他插件，这是取消注册制的直接原因。
  • 无宿主 API：没有 open / close 动作——层的出现与消失就是普通 React 组件的挂载与卸载。
  • 无数据往来：宿主不经手任何东西，所以本目录没有数据流页。

四条底线 已定

底线为什么
画在自己的组件里
用 position: fixed		portal 到 body 会逃出 [data-pi-plugin] 样式作用域，插件样式全丢；fixed 定位天生视口级，不需要 portal
卸载即消失弹窗是组件树的一部分：插件被禁用 / 卸载时随组件卸载，无残留，宿主不用收拾
永远压不过宿主卡权限审批卡、确认卡队列在宿主最高层带，这是宿主自己定死的；插件层低一档（z 序带见下）
插件之间不仲裁两三个插件同时浮层：后开的在上（DOM 顺序），遮罩叠加是可接受的结果；真实的协调需求出现前，宿主不做登记机制
崩溃照常被兜。自理界面在插件组件里渲染，槽级出错隔离罩得住：抛错塌的是这个插件自己的界面，邻居与应用不受影响。

样式说明 已定 推荐值

插件界面长在宿主页面里，必须跟着主题走。宿主的视觉系统只有一个来源：apps/desktop/src/styles/tokens.css——dark 是 :root 默认，light 在 :root[data-theme="light"] 覆盖。只用 token，不写死字面量：写死的深色在用户切到浅色主题时会直接坏掉。

必用的主题 token

用途token说明
弹层表面--ds-bg-elevated-opaque所有浮层家族（对话框 / 通知 / toast）共用的不透明 elevated 底
边--ds-border-default / --ds-border-subtle浮层的 1px 边是「高度提示」，用这两个，不是分隔线
阴影--ds-shadow-dialog对话框级阴影，浮层家族统一用这一个
遮罩--ds-scrim模态遮罩；dark ~45% 黑、light ~28% 墨，主题自动切
圆角--radius-lg-plus（卡）/ --radius-md-plus（通知 / toast）圆角梯队是唯一的圆角来源
文字--ds-text-primary / secondary / muted三级文字墨水，别自造灰
状态色--ds-success / warning / error只用于图标 / 点缀，表面保持中性
动效--motion-duration-normal + --motion-ease-out入场动画对齐宿主浮层的节奏（下移 8px 淡入）
字号 / 字重--text-* / --font-weight-*字阶同样禁止字面量

你要画什么参照宿主的形态要点

别挂宿主的内部类名。.search-dialog 这些是宿主实现细节，会随宿主重构漂移。 sanctioned 的公共面是下面两样：主题 token（CSS 变量，会继承进插件容器）+ 宿主打包的插件工具类（见下）。

工具类 / 样式片段（宿主打包） 已定

把上面的推荐形态打包成插件可用的官方工具类：跟随主题、随宿主升级自动演进，插件直接挂类名使用，不再各自复刻。

  • 弹窗：pi-dlg-overlay（全屏 + 遮罩）+ pi-dlg（居中卡：表面 / 边 / 阴影 / 圆角）+ 头部 / 内容 / 按钮排片段。
  • 悬浮层：pi-notice（角落通知卡：32px 图标位 + 标题 + 正文 + 关闭钮）+ pi-toast 形态。
  • 悬浮层拖动：拖动手势随工具类一起提供（只悬浮层，弹窗不拖）；插件不用自己实现。
  • 命名以 pi- 前缀与宿主内部类名划清界限；这组类名是稳定的插件公共面，变更走兼容流程。

交互规则 已定

规则说明
Esc 不关闭自理弹窗不响应 Esc——与确认卡 / 权限审批卡一致，关闭必须经由明确的界面动作
关闭只走 ✕ 钮弹窗和悬浮层都必须有可见的关闭（✕）钮，且关闭只走它：点遮罩不关、Esc 不关——用户永远有一条明确、不用键盘的退出路
只有悬浮层可拖动悬浮层建议支持拖动（角落通知卡等），手势随工具类提供；模态弹窗不拖，固定居中
不记拖动位置拖到哪算哪，不随会话记忆；每次打开回默认位置

z 序带 已定

宿主现有的层带（styles/overlays.css）：叶子弹层 60 / toast 50 / 角落通知 45 / 对话框 40。自理层建议 ≤ 39，且永远低于宿主审批卡与确认卡——这是底线第三条的具体数值。越带宿主不拦截，但越带会在宿主浮层出现时被盖住，属于自担后果。

问题结论
弹窗 / 悬浮层宿主管不管不管。插件自理；宿主删掉 modal / overlay 槽与 ui.openModal 等四个动作（实现批次处理）
多插件抢注怎么办没有注册就没有抢注。并发时后开的在上，宿主不仲裁
样式从哪来主题 token（tokens.css）+ 宿主打包的官方工具类（pi-dlg / pi-notice 等，含拖动手势）；不挂宿主内部类名；z 序 ≤ 39
Esc 关不关自理弹窗不关。与确认卡 / 权限审批卡一致，关闭走明确的界面动作
关闭路径关闭只走 ✕ 钮：弹窗与悬浮层都必须有可见的 ✕，点遮罩不关、Esc 不关
能不能拖只悬浮层建议拖动（手势随工具类提供）；模态弹窗不拖、固定居中
拖动位置记不记不记。每次打开回默认位置
多插件并发维持「后开在上、不仲裁」
工具类打不打包打包。推荐形态成为宿主提供的插件工具类（pi- 前缀、稳定公共面、随宿主升级跟随主题）
本文件夹要不要数据流页不要。宿主不经手任何数据；本页记录此决定
和确认卡的关系分工：问一句话 → ui.confirm()（ui/layers/）；自由界面 → 本目录自理

还没定的事 未定

  • 工具类的具体类名清单与打包位置（SDK 还是样式文件），实现批次定。

明确不做 已定

  • 宿主不做槽、不做注册、不做抢注仲裁、不做强制收起（卸载随组件消失已覆盖清理）。
  • 不让自理层进确认卡 / 权限审批卡的决策路径，也不允许压过它们。
  • 不做 Shadow DOM（会逃出宿主 portal，见 spec 16 §2A.3 的既有结论）。
