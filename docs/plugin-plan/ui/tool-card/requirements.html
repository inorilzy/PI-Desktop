工具调用卡 · 需求

对话里每一次工具调用显示的那张卡。一个槽 tool-card：插件按工具名认领，拿到固定格式的数据 + 宿主默认卡组件。本期只做展示。

status: draft · issue #545 · 对照 demo.html / data-flow.html

范围 已定

  • 只谈对话流里工具调用卡的显示：宿主内置工具、插件工具、MCP 工具，都指这一张卡。
  • 本期只做展示相关：卡的职责是把这次调用的入参和结果显示好。
  • 不谈：工具执行本身（改参数、拦截、放行是另一个槽）、Composer 里的确认卡和计划审批栏、助手正文气泡。

槽有几个 已定

槽位置插件能做什么
tool-card这一次工具调用的卡整体可以整块自己画；也可以原样复用宿主默认卡，在它外面或下面再包一层

槽只有这一个，但插件可以按工具名认领多次——同一个插件能给不同的工具画不同的卡。

按工具名认领。插件在清单里声明自己要接哪些工具；没被认领的工具永远走宿主默认卡。宿主不认领，默认卡就是兜底。

槽必须提供三件套 已定

件含义
完整数据（固定格式）工具很多、返回各异，宿主先归一成一份固定格式的数据再交给插件：这是哪个工具、入参是什么、跑到哪一步、结果是什么。原始返回块原样附在数据里，不丢信息。
现成组件（默认卡）宿主把默认卡整体做成现成组件交给插件：想「跟 UI 一样」就原样渲染它，在外面加东西；想重绘就不用它。
能调用的操作展示类的宿主功能：打开文件 / 网址预览、复制文本。都是直接可调的函数，不是名字。

目的：插件把卡画坏了，最多是这一次调用不好看；调用怎么存、会话怎么继续，还是宿主说了算。

默认卡长什么样 已定

按宿主现在的实际形态（demo 场景 1），无底色的扁平行，不是一张盒子卡：

头部（一直显示，一行）

  • 图标 + 动作词（如 读取 src/lib/retry.ts），词随状态变化（读取 / 正在读取）
  • 摘要参数（等宽字），结果小芯片（行段 / 条数 / 退出码 / 体积 / 已截断，方角）
  • 状态：运行中是转圈，失败是红色「失败」，成功不显示任何状态；运行类（Bash）额外给命令复制按钮和「点 + 已完成 / 失败」
  • 行尾旋转箭头（可展开才有），展开时转 90°

展开体（行下，分块）

  • 每块一个小标题（文件内容 / 匹配 / 详情…）+ 复制按钮，块体是 tile 底圆角容器
  • 按工具类型分块：代码、文件列表、命中列表、字段表、提示条；对不上的形状落回「字段表」兜底
  • 运行类的输出不带框，像终端原文，错误输出红色

子代理（Task）是另一张卡

  • tile 底聚合卡：「Subagent 已完成 · 1 个 Subagent · 已完成 1/1 · 24s」，展开是节点列表（头像 + 名字 + 模型 + 结果）

demo 场景 1 就是它们，包括没被任何插件认领的 MCP 工具的字段表兜底形态。

本轮拍板 已定

问题结论
只做展示是。凡是等待性质的——下一步、审批、确认、重试再跑——本期一律不做
谁可以认领任何插件都能认领；对所有工具调用生效，不看这条消息是谁产生的
没认领的工具保持宿主默认卡，一个字都不变
数据格式所有工具共用一份固定格式；插件按这份格式取数，不为每个工具写一套解析
运行中 / 失败态也走槽：状态和节流后的新数据一并递给插件，插件决定怎么画
认领键支持到什么程度只支持工具全名，不做前缀 / 按动作通配
两个插件认领同一个工具安装的时候提示冲突，让用户当场决定
Write / Edit 旁边的改动审阅卡从工具卡旁边移走，固定显示在输入框上方；它不再属于工具卡区域
大结果给插件给多少全量给，不设上限、不截断；显示什么、怎么省是插件自己的事。数据里的「已截断」只反映工具自己截了（如 Bash 超长输出），宿主不额外截
折叠展开状态谁管插件管：插件认领的卡自己记展开态；宿主只在插件让位（报错 / 关闭）切回默认卡时用默认的展开规则

和 #545 原文的关系 边界改口

#545 原文仅供参考，边界以本页为准。这是产品决定，不是实现漏项。

#545 原文的想象

  • 工具卡上可以有插件放的交互按钮、走向下一步
  • 插件深度参与工具执行的来来回回

本轮决定

  • 卡只负责展示；等待 / 审批性质的东西一律不做
  • 执行拦截、参数改写是另外的槽，不在 tool-card 里

接口长什么样（建议，还没定） 建议

下面是支撑上面拍板的东西，不是用户原话；字段名开工时再定。完整版见 data-flow.html 的第一节。
  • 认领声明：清单里 toolCards: [{ tool: "mcp_github_get-issue" }]，只按工具全名；两个插件认领同一个名字时在安装时提示冲突。
  • 固定数据：tool（名字 / 来源）+ call（入参 / 状态 / 耗时）+ result（拼好的文本 / 结构化对象 / 原始块）+ error。
  • 现成组件：ToolCard（整张默认卡）、CodeBlock / FileList / MatchList / FieldsTable 这几块展开体，想用就用。
  • 能调用的操作：openPreview / copy。

还没定的事 本轮收口

本轮的问题都已拍板。子代理的拓扑画布和工作面板侧栏本轮不开放认领；将来要放开时另开一轮。

明确不做 已定

  • 等待 / 审批性质的卡：下一步、审批、确认、重试再跑——本期一律不做；需要等用户点头的流程不在这个槽里。
  • 不让插件改工具的入参、拦截或放行执行——那是工具执行槽的事。
  • 不让插件调用工具本身、发起新的工具调用。
  • 不给整段对话、旁边的卡、别的会话——槽只拿到这一次调用的数据。
  • 不做多张卡合并成一个视图；一张卡对应一次调用。
