工具调用卡 · 数据流

插件能拿到什么（一份固定格式的数据）、自己画什么、出错时发生什么。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · 接口里的字段名是建议值，还没定

1接口约定 建议

权限名沿用 renderer.extension：一个权限名管所有组件插槽，不用每个槽单独授权。

认领方式（插件清单里声明）

{
  toolCards: [
    { tool: "mcp_github_get-issue" },      // 只按工具全名认领，不做通配
    { tool: "plugin_demo_db-query" },
    { tool: "plugin_demo_code-stats" }
  ]
}
两个插件认领同一个全名：安装的时候提示冲突，让用户当场决定。已定的是：没被认领的工具永远走宿主默认卡。可认领的内置工具全名单见 requirements.html；Task / TaskWait / TaskList / TaskStop 本轮不开放认领（拓扑画布与工作面板侧栏是独立的一层），认领了也不生效。

插件能拿到的数据（固定格式）

工具很多、返回各异。宿主先把每一次调用归一成下面这一份，再交给插件；所有工具共用这一份格式。原始返回块原样附在 result.content 里，不丢信息。

{
  tool: {
    name,                        // 完整工具名，也是认领键：Read / mcp_github_get-issue / plugin_demo_db-query
    display,                     // 给人看的名字
    source: "host" | "plugin" | "mcp",
    pluginId?, serverId?         // 来源是谁，host 来源没有这两项
  },
  call: {
    id,                          // 这次调用的 id
    args,                        // 入参，工具收到什么这里就是什么
    status: "running" | "success" | "error",
    startedAt, durationMs,
    usage: { argumentTokens, resultTokens, totalTokens }
  },
  result: {
    text,                        // 拼好的文本结果（多段按顺序拼）；没有就是 null
    data,                        // 结构化结果（宿主详情或 MCP structuredContent），对象原样；没有就是 null
    content: [                   // 原始返回块，按工具返回的顺序
      { type: "text", text } | { type: "image", data, mimeType } | { type: "resource", … }
    ],
    isTruncated, notice
  },
  error: { message, code } | null
}
全量给，不设上限、不截断。显示什么、怎么省是插件自己的事。数据里的 isTruncated 只反映工具自己截了（如 Bash 超长输出），宿主不额外截。

宿主提供的现成组件

想「跟 UI 一样」就渲染 ToolCard；想重绘可以只借里面的块组件。不是必须套的外壳。

组件画什么不用它的话，插件要自己做什么
ToolCard整张默认卡：头部（动作词 / 摘要 / 芯片 / 状态点）+ 展开体头部和展开体的全部信息自己排
CodeBlock带行号和语法高亮的代码块高亮、行号、滚动自己处理
FileList可点击的文件列表点击打开走 openPreview
MatchList按文件分组的命中列表（带行号、命中高亮）分组和高亮自己处理
FieldsTable字段名 / 值两列表排版自己处理
Chips结果小芯片（行数 / 条数 / 退出码 / 已截断）数字自己算

插件能调用的操作

操作做什么什么时候不能用
openPreview(target)用宿主现有的方式打开文件 / 网址（工作面板 / 文件视图 / 内置浏览器）目标不存在时给个提示
copy(text)把一段文本放进系统剪贴板—
就这两个。凡是能让对话「等一下」的操作——提交、审批、取消调用、重新执行——都不在这个槽里。

调用的一生，卡收到什么

阶段数据里的变化宿主做什么
开始执行status: "running"，args 已完整，result 为空按认领把卡交给插件
执行中流式输出按节拍（约 0.1 秒）更新 result，状态一直是 running每次更新把新的一整份数据递给插件重画；插件不用自己订阅
成功 / 失败status 变成 success / error，result / error 给全，附耗时最后一次递数据，之后这张卡不再变
历史回放重开会话时直接是终态数据跟实时成功 / 失败同一个渲染路径

谁能认领、认领了管多大

规则
谁任何插件都能认领；对所有工具调用生效，不看这条消息是谁产生的
范围只认工具全名，不做前缀 / 按动作通配；一个声明管这一种工具的全部调用，同一个插件可以声明多个
粒度整卡替换或整卡复用，不做「只换头部 / 只换展开体一半」的局部替换
本轮不做等待性质的卡：审批、确认、下一步、重试再跑。需要用户点头的流程是另外的槽，不在 tool-card 的数据里。

3出错怎么办 一定会遇到

情况这张卡会变成什么靠什么保证
组件报错 / 卡死换回默认卡；旁边的卡不受影响每张卡独立的出错隔离
插件被关掉 / 崩溃 / 禁用这张卡变回默认卡，不留空位；历史记录里的卡也一样插件不在就不占位置
工具本身失败不是插件出错：数据里 status: "error" + error，插件照常画，也可以不画错误（宿主兜底卡会画）工具失败和插件失败分开
流式中途出错最后一份 error 数据递给插件，之后卡定格同一份数据格式
插件没声明 renderer 入口认领声明跳过注册，普通插件不受影响信任档
挡不住的：受信插件故意把卡画坏，比如把错误藏起来、把结果画反。它和宿主跑在同一个页面进程里，这是已经接受的代价。能保证的是：它改不了这次调用的记录，也弄不垮整场对话。

4不提供什么 已定

不给为什么真需要就走哪
等待性质的操作审批 / 确认 / 下一步 / 重试会让对话停在卡上等用户点头，这不是展示卡该管的事本轮没有这条路；将来是另外的槽
执行控制改入参、拦截、放行、取消是工具执行的事，跟显示分开runtime/tool-gate（还没开）
发起新调用卡不能反过来调用工具，否则显示和执行绕回去了本轮没有这条路
整段对话、旁边的卡槽只拿到这一次调用的数据没有这条路
改记录的权力调用的入参和结果是历史记录，插件不能改没有这条路
