块渲染器 · 需求

AI 回复里的每一个 fenced code block。一个槽 block-renderer：插件按代码块的语言标签认领，接管这一块的渲染。宿主只把代码块原文交出去，其余都是渲染器自己的事。

status: draft · issue #545 · 对照 demo.html（已确认，2026-09-21）

范围 已定

  • 只谈对话流里 AI 回复正文的 fenced code block（```语言标签 … ```）怎么显示：普通代码、数据、图形描述，都指这一块。
  • 宿主已经内置了两种「代码块即渲染」：```mermaid 画流程图、LaTeX 数学公式走 KaTeX。这个槽是把同样的位置开放给插件。
  • 不谈：代码块内容的产生（模型怎么写、能不能引导模型输出某种格式）、消息正文其他部分的渲染、工具调用卡（另一个槽 tool-card）。

槽有几个 已定

槽位置插件能做什么
block-renderer一个闭合的代码块整体（含头部那条语言栏的位置）整块自己画。头部、操作按钮、错误提示都是渲染器自己的（demo 场景 2/3）

槽只有这一个，但插件可以按多个语言标签认领——同一个插件能给 chart、csv 各画不同的样子。

按语言标签认领 已定

认领键是围栏后那个语言标签（```chart 的 chart），跟 tool-card 按工具全名认领是同一个思路：

问题结论
认领键支持到什么程度只支持语言标签全名，不做前缀、不做通配
大小写不区分大小写（```Chart 和 ```chart 算同一个）
两个插件认领同一个标签安装的时候提示冲突，让用户当场决定（与 tool-card 一致）
宿主内置的标签mermaid 是宿主内置渲染器，不接受认领；数学公式不走代码块认领
没被认领的标签永远走宿主默认代码块。宿主不认领，默认代码块就是兜底；这个兜底同时服务三种回退（见下）。

宿主交出什么 已定

只有两样，一次交清：

给什么是什么
语言标签认领命中的那个标签原文
代码块原文围栏内的全部文本，原样、全量、不解析。宿主不规定内容格式——chart 里写什么 JSON、csv 里逗号还是分号，是渲染器和模型之间的事
复制、看源码、错误提示，渲染器自己实现。宿主不递现成组件、不递可调用的操作，也不递别的数据——这就是「不强行传递什么」。渲染器要一个复制按钮就自己画一个（demo 场景 2 头部的两个按钮是插件画的）。

这与 tool-card 是刻意相反的选择：那边工具返回五花八门，宿主先归一成固定格式再给；这边代码块里写什么是模型和渲染器自己的约定，宿主解析反而多余。

什么时候回退默认代码块 已定

时机显示什么demo
标签没被任何插件认领宿主默认代码块场景 1
流式中围栏还没闭合宿主默认代码块（内容边到边显示），闭合后才切换成渲染结果场景 4
内容渲染失败渲染器自己显示错误和源码（demo 里的红色错误行是插件画的）场景 4
插件停用 / 卸载宿主默认代码块，同一段原文原样显示场景 4

共同点：回退时显示的就是宿主默认形态，原文一个字不丢——默认代码块随时能接住任何一块。

本轮拍板 已定

问题结论
有没有「数据流」没有。宿主只在渲染那一刻把「标签 + 原文」交给渲染器，之后没有任何数据往来。本文件夹因此不设数据流页
复制 / 源码切换 / 错误提示渲染器自己实现，宿主不递组件、不递操作、不强行传任何东西
内容格式宿主不规定。每种标签的内容格式是渲染器自己定义、模型照着写的
流式中围栏没闭合永远显示默认代码块，闭合才接管；渲染器不会收到半截内容
插件停用同一段原文回到宿主默认代码块，不重排、不丢内容

怎么注册（建议，还没定） 建议

落到宿主现有的清单结构（contributes.* 声明式贡献，和 themes / providers 同一层）：

  • 清单声明：contributes.blockRenderers: [{ languages: ["chart", "csv"] }]。认领在安装时校验冲突，插件停用后认领随之失效。
  • 渲染器本体：插件自带的一个沙箱页面（和面板页面同一套隔离）。宿主在渲染那一刻把 { language, source } 递进去，页面返回要显示的内容。复制按钮这类交互都发生在这个页面里，宿主不经手。
  • 宿主侧挂钩点就在现在拦 mermaid 的那个位置（代码块 → 查注册表 → 命中交给渲染器，未命中走默认代码块），不需要新的渲染管线。
还在犹豫的：同一标签是否允许「复用宿主默认代码块再外包一部分」（像 tool-card 的「复用默认卡 + 追加」）；本页按整块接管、不做混合起草，理由是代码块没有默认卡那套可拆的展开结构。

还没定的事

  • 要不要权限名（ui.blockRenderer 之类），还是归进现有 UI 权限。
  • 信息串里标签后面的附加词（```chart pie 的 pie）要不要原样递给渲染器。
  • 渲染器页面的高度约定：内容撑高谁来定、超长怎么滚，是否沿用面板的最小/最大尺寸。
  • 渲染器崩溃（页面级错误，不是内容不合法）时宿主兜底的提示样式。

明确不做

  • 不递消息上下文：整段回复、这条消息是谁发的、别的代码块——渲染器都拿不到，它只看到自己这一块。
  • 不让渲染器改写消息原文：存储、复制全文、引用跳转里的代码块还是原文，渲染只发生在显示层。
  • 不让渲染器发起工具调用、访问文件和网络——渲染器页面没有这些能力，也不通过它绕道。
  • 不做多块联动：一个渲染器实例只对应一个代码块，块与块之间不通信。
  • 不做半截渲染：流式中围栏未闭合不进渲染器（demo 场景 4）。
